Chapter · Driver clustering

Grouping by observed behaviour

Objective and scope

The clustering module groups drivers, identified by licence plate, from behavioural indicators extracted from vehicle detection records (flujos). Its output has two roles: first, it supports exploratory analysis of driving profiles; second, it produces labels and membership probabilities that are aggregated by gantry and interval for accident prediction, drift detection, and later simulation scenarios.

In the LaTeX documentation, the clustering chapter and the feature-engineering detail were separated. In the web documentation they are consolidated here because both describe one methodological contract: transform raw events \((t,p,\ell,v,\text{plate})\) into a per-driver vector, train clustering models, and project those groups into traffic-level macro variables.

Input data and observational unit

The elementary unit is one vehicle pass through a gantry. For \(N\) records, each event is represented as:

Data preprocessing

Cleaning is part of the scientific contract because it defines which observations can construct driver profiles. Plates are normalized with normalize_plate_series, removing non-alphanumeric characters, converting to uppercase, and discarding invalid values such as "", nan, null, or none. The implementation keeps only plates with length between 5 and 6 characters.

Lane is converted to numeric and restricted to \(\ell\in\{1,2,3\}\). Deduplication uses the key \((\mathrm{plate},p,\ell,t)\). If duplicates have different speeds, stable sorting preserves one deterministic observation, preventing results from depending on accidental file order.

\[ v_j^{\star}=\min\{\max(v_j,q_{\alpha,p,\ell}),q_{\beta,p,\ell}\},\qquad \alpha=0.01,\ \beta=0.99\ \text{by default}. \]
(1.2)
Variables
v*j
Winsorized speed.
qα,p,ℓ, qβ,p,ℓ
Speed quantiles computed inside each gantry-lane group.
Modes

Clips extreme values inside the quantile range.

Behavioural feature detail

For each plate \(i\), the module builds a vector \(x_i\in\mathbb{R}^d\). Default columns include avg_speed_kmh, exceso_velocidad, avg_relative_speed, avg_headway_s, conflict_rate, lane_prop_1, lane_prop_2, and lane_change_rate. lane_prop_3 is computed but redundant given the other proportions and is normally omitted during training.

Speeding

The module queries load_portico_maxspeed_map and estimates the fraction of events where \(v_j\) exceeds the gantry speed limit. If no valid limit exists, the column is defensively filled with zero and, when include_counts=True, speed_limit_count is retained to audit how many events had a real denominator.

Indexed relative speed

To control for local traffic regime, raw speed is not compared to a global mean. A reference speed is computed by gantry and 5-minute window:

\[ \overline v_{p,\tau}=\frac{1}{|\mathcal{I}_{p,\tau}|}\sum_{j\in\mathcal{I}_{p,\tau}}v_j,\qquad \rho_j=\frac{v_j}{\overline v_{p_j,\lfloor t_j\rfloor_{5\mathrm{min}}}},\qquad \overline\rho_i=\frac{1}{|\mathcal{J}_i|}\sum_{j\in\mathcal{J}_i}\rho_j. \]
(1.4)

Headway

Headway requires strict temporal ordering. Events are grouped by gantry and lane and shift(1) retrieves the preceding vehicle. In monthly mode, the group also includes month, so boundaries between months do not create artificial interactions.

\[ \begin{aligned} h_j &= t_j-t_{j-1},\\ \overline h_i &= \frac{1}{|\mathcal{H}_i|}\sum_{j\in\mathcal{H}_i}h_j,\\ \mathcal{H}_i &= \{j:\mathrm{plate}_j=i,\ 0\lt h_j\le h_{\max}\}. \end{aligned} \]
(1.5)

TTC, thresholds, and conflict rate

TTC is defined only for closing pairs, meaning the current vehicle is faster than the preceding one in the same gantry-lane. The threshold can be dynamic by gantry (TTC_MAX_BY_PORTICO) or fixed for all gantries (DEFAULT_FIXED_TTC_SECONDS=1.5 by default).

\[ \begin{aligned} \Delta v_j &= v_j-v_{j-1},\\ \mathrm{TTC}_j &= \frac{h_jv_j}{\Delta v_j}\quad(\Delta v_j>0),\\ \theta_j &= \begin{cases} \tau_{p_j}, & \text{dynamic mode},\\ \tau_{\mathrm{fixed}}, & \text{fixed mode}. \end{cases} \end{aligned} \]
(1.6)

Lane changes

Lane change is estimated by ordering passes by plate and timestamp. This metric is approximate because gantries are discrete observations rather than a continuous trajectory; still, it captures observed lateral variability between consecutive detections.

\[ \begin{aligned} \mathrm{lane\_changes}_i &= \sum_{m=2}^{N_i}\mathbf{1}[\ell_{i,m}\ne\ell_{i,m-1}],\\ \mathrm{lane\_change\_rate}_i &= \frac{\mathrm{lane\_changes}_i}{\max(N_i-1,1)}. \end{aligned} \]
(1.8)

Temporal activity

Beyond behaviour, the module measures historical persistence: n_days_active, n_weeks_active, n_months_active, and n_years_active. These columns are used to split frequent drivers and to select prevalent plates in dynamic GMM. Months are counted as calendar year-month pairs.

\[ \begin{aligned} n_i^{(\mathrm{days})} &= |\{\lfloor t_j\rfloor_{\mathrm{day}}:\mathrm{plate}_j=i\}|,\\ n_i^{(\mathrm{weeks})} &= |\{\lfloor t_j\rfloor_{\mathrm{week}}:\mathrm{plate}_j=i\}|,\\ n_i^{(\mathrm{months})} &= |\{\lfloor t_j\rfloor_{\mathrm{month}}:\mathrm{plate}_j=i\}|. \end{aligned} \]
(1.9)
Downstream use
split_frequent_drivers · build_prevalent_plate_selection

Monthly weighting

When monthly_weighting=True, variables are computed by plate-month and then consolidated by weighting each month by its pass count. This prevents low-volume months from having the same influence as high-activity months.

\[ \overline{x}_i=\frac{\sum_m N_{i,m}x_{i,m}}{\sum_m N_{i,m}}. \]
(1.10)

Data preparation for clustering

The user selects numeric feature columns. Before training, values are coerced to numeric, infinities are replaced by NaN, and incomplete rows are dropped. Then z-score standardization is applied with sklearn.preprocessing.StandardScaler. If training uses only frequent drivers, the scaler is fitted on that subset and applied to the rest.

\[ z_{i,f}=\frac{x_{i,f}-\mu_f}{\sigma_f}. \]
(1.11)

Frequent vs. rare

split_frequent_drivers separates plates with enough support using total_passes, n_days_active, n_weeks_active, and n_months_active when available. K-means assigns rare drivers by centroid distance and percentile threshold; GMM assigns rare drivers by maximum posterior probability. If confidence falls below the threshold, the label is unknown (\(-1\)).

Dynamic GMM clusters

The dynamic GMM experiment asks whether membership learned from historical behaviour remains stable or changes when only recent behaviour is observed. The baseline model is trained once on loaded historical features; then each window recomputes Clusterization from flujos, transforms with the historical scaler, and predicts with the fixed GMM. The model is not retrained inside each window.

\[ \begin{aligned} W_s&=[d_s,d_s+x\ \mathrm{days}),\\ d_{s+1}&=d_s+1\ \mathrm{day},\\ r_{i,s,k}&=p(z=k\mid S(x_{i,s})). \end{aligned} \]
(1.15)

Prevalent variant

The prevalent dynamic GMM variant keeps the same historical training but restricts assignment to an exact fraction of the most persistent plates. Plates are ranked by descending n_months_active, descending n_years_active, descending total_passes, and ascending plate.

\[ n_{\mathrm{prev}}=\max\left(1,\left\lceil n_{\mathrm{plates}}\frac{q}{100}\right\rceil\right). \]

Aggregated variables by gantry and interval

Clustering labels are also projected into macro variables. From a plate \(\rightarrow\) cluster_label table, each gantry-interval-cluster cell can be aggregated with hard or soft membership. Soft membership uses cluster_prob_* when the file comes from static or dynamic GMM.

\[ \begin{aligned} n_{p,\tau,c}&=\#\{j:p_j=p,\lfloor t_j\rfloor_{\Delta}=\tau,\mathrm{cluster}(\mathrm{plate}_j)=c\},\\ w_{p,\tau,c}&=\sum_{j:p_j=p,\lfloor t_j\rfloor_{\Delta}=\tau}r_{j,c}. \end{aligned} \]
(1.19)
Modes
Hard
Counts discrete labels.
Soft
Sums GMM responsibilities and preserves rare-driver contribution.
\[ \begin{aligned} \mathrm{share}_{p,\tau,c}&=\frac{m_{p,\tau,c}}{\sum_{c'}m_{p,\tau,c'}},\\ \mathrm{flow}_{p,\tau,c}&=m_{p,\tau,c}\frac{60}{\Delta}\frac{1}{L},\\ H_{p,\tau}&=-\sum_c\mathrm{share}_{p,\tau,c}\log\mathrm{share}_{p,\tau,c}. \end{aligned} \]
(1.20)

Technical audit

Implemented strengths
  • Plate, lane, timestamp, and speed cleaning occurs before any aggregation.
  • Headway and TTC are computed with stable ordering and only inside the same gantry-lane.
  • The TTC mode is persisted in metadata, including dynamic map or fixed threshold.
  • GMM responsibilities enable soft membership and avoid discarding rare-driver information.
  • Dynamic GMM uses a fixed historical model and recomputed windows, separating behavioural drift from retraining.
  • Prevalent selection uses deterministic ranking and a plate hash for checkpoint validation.
Methodological risks
  • lane_change_rate approximates changes between discrete detections; it does not observe continuous maneuvers.
  • Headway and conflict depend on temporal quality and on the preceding vehicle being captured.
  • The dynamic TTC threshold is empirical by gantry and must be reported with results.
  • Cluster comparisons are valid only with the same features, scaler, \(K\), frequent-driver filters, and historical period.
  • Soft aggregation requires cluster_prob_* from a model compatible with the evaluated period.

Plate as unit

Clustering is trained by plate, not by event. Each vector summarizes history, interaction, lane behaviour, and activity.

TTC. It can use a dynamic gantry map or a fixed threshold. That decision changes conflict rate.

GMM. When cluster_prob_* exists, downstream stages can use soft membership.

Dynamic. Windows do not retrain the model: they measure behavioural change relative to the historical GMM.
