Chapter · Driver clustering

Grouping by observed behaviour

Goal

The module groups drivers —identified by their licence plate— according to behavioural indicators observed in the detection records (flujos). The groups are used for exploratory analysis and to build aggregated variables per gantry and interval that feed the downstream models.

Data and preprocessing

We start from observations \( r_j = (t_j, p_j, \ell_j, v_j, \text{plate}_j) \) with time, gantry, lane, speed and plate. Normalisation upper-cases the plate, drops invalid values ("", nan, null, none) and filters lengths outside \([5,6]\). Lanes are restricted to \(\ell\in\{1,2,3\}\) and exact duplicates by key \((\text{plate}, p, \ell, t)\) are removed.

For speed-outlier handling, per group \((p,\ell)\) quantiles \(q_\alpha\) and \(q_\beta\) are computed; depending on the mode we apply winsorisation \(v\leftarrow\min(\max(v,q_\alpha),q_\beta)\), hard filtering, or none.

Per-driver feature engineering

A vector \(x_i\in\mathbb{R}^d\) is built by aggregating over driver i's passes. Artefacts are stored in Resultados/cluster_features*.duckdb (table cluster_features).

Relative speed

Over 5-minute per-gantry intervals a reference mean speed \( \overline{v}_{p,\tau} \) is defined. For each pass, \( \rho_j = v_j/\overline{v}_{p_j,\lfloor t_j\rfloor_{5\text{min}}} \), and per driver \( \overline{\rho}_i = \frac{1}{|\mathcal{J}_i|}\sum_{j\in\mathcal{J}_i}\rho_j \).

Headway

Per group \((p,\ell)\) ordered by \((t,\text{plate})\): \( h_j = t_j - t_{j-1} \) in seconds. Headways larger than \(h_{\max}=60\,\text{s}\) are treated as missing.

\[ \overline{h}_i = \frac{1}{|\mathcal{H}_i|}\sum_{j\in\mathcal{H}_i} h_j,\qquad \mathcal{H}_i=\{j:\text{plate}_j=i,\ 0<h_j\le h_{\max}\} \]

TTC and conflict rate

For each pass with a previous vehicle in the same \((p,\ell)\), define \(\Delta v_j=v_j-v_{j-1}\). A finite TTC exists only for closing pairs (\(\Delta v_j>0\)): \( \mathrm{TTC}_j = h_j v_j / \Delta v_j \). A per-gantry threshold \(\tau_p\) (TTC_MAX_BY_PORTICO) is fixed. The driver-level rate uses all pairs with valid headway and an observed previous speed in the denominator; non-closing pairs contribute zero:

\[ \mathrm{conflict\_rate}_i = \frac{\sum_{j\in\mathcal{K}_i}\mathbf{1}[\Delta v_j>0\ \land\ \mathrm{TTC}_j<\tau_{p_j}]}{|\mathcal{K}_i|},\qquad \mathcal{K}_i=\{j:\text{plate}_j=i,\ h_j>0,\ v_{j-1}\ \text{defined}\} \]
(1.3)

Lane changes and activity

Lane changes are counted by ordering by driver and time: \(\mathrm{lane\_changes}_i = \sum_{m=2}^{N_i}\mathbf{1}[\ell_{i,m}\neq\ell_{i,m-1}]\) and its rate. Temporal activity includes counts of active days, weeks and months.

Clustering methods

Before clustering, z-score is applied with StandardScaler. Three families are compared:

  • K-means: minimises \(\sum_i \lVert x_i-\mu_{c_i}\rVert^2\). Selection of \(K\) is guided by Silhouette, Davies–Bouldin and Calinski–Harabasz.
  • GMM: \(p(x)=\sum_{k=1}^K\pi_k\mathcal{N}(x\mid\mu_k,\Sigma_k)\) via EM; \(K\) is chosen by AIC/BIC.
  • HDBSCAN: density-based hierarchy with min_cluster_size and min_samples; noisy observations get label \(-1\).
Frequent vs. rare

For robustness, the model can be trained only on frequent drivers (\(N_i\ge N_{\min}\)). Rare drivers are then assigned a label by centroid distance (K-means) or maximum posterior (GMM); if confidence falls below a threshold they are marked unknown (\(-1\)) and confidence_score is stored alongside is_rare.

Operational preprocessing

  1. Plate normalisation: alphanumeric, upper-case, length in \([5,6]\); NULL, NAN filtered.
  2. Lane filter to \(\{1,2,3\}\).
  3. Deduplication by \((\text{plate},p,\ell,t)\).
  4. Speed winsorisation per \((p,\ell)\), when enabled, using the configured quantiles.

Per-plate aggregation and consolidation

For each driver, the module aggregates mean speed, relative speed, headway, conflict rate, lane usage, lane-change rate and temporal activity. Under monthly weighting, each monthly statistic is weighted by the observed monthly volume.
