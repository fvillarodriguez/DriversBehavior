Accident prediction

Goal and sources

Build and evaluate models that predict the occurrence of an accident at a gantry, from aggregated flow variables and, optionally, variables derived from driver clusters. Flows are stored in DuckDB. Accidents come from event files filtered by type Accident and Road, with accidente_time and a mapping to nearby gantries via Datos/Porticos.csv; the assigned gantry is stored as ultimo_portico.

Optionally, per-gantry first differences \( \Delta\overline{v} \) and \( \Delta k \) are added, producing a wide matrix with columns flow_<cat>, speed_<cat>, density_<cat>, etc.

Cluster variables (optional)

If the table plate → cluster_label exists, detections are joined with their cluster \(\kappa\) and aggregated by \((p,\tau,\kappa)\). The mix entropy \( H_{p,\tau}=-\sum_\kappa\mathrm{share}_{p,\tau,\kappa}\log\mathrm{share}_{p,\tau,\kappa} \) is also added. They are stored as cluster_share_*, cluster_flow_*, cluster_speed_*, etc.

Target definition

An accident at \((t_a,p_a)\) is labelled at the previous interval: \( \tau_a = \tau(t_a) - \Delta \), with

\[ y_{p,\tau} = \begin{cases} 1, & \text{if there is an accident with }(p_a,\tau_a)=(p,\tau) \\ 0, & \text{otherwise} \end{cases} \]
(2.4)
Variables
yp,τ
Binary target "an accident will happen in the next interval".
τa
Bin preceding the accident (one-Δ lead time).
Implementation
src/drift_detection_app.py · _add_interval_accident_target

Hence \( y_{p,\tau}=1 \) means "an accident will happen in the next interval".

Split, imbalance and models

To avoid temporal leakage, the split is chronological by interval_start: the final stretch is the test set (test_size). Inside the train/val block, validation is isolated with val_size. Imbalance is handled with class weighting (class_weight="balanced" in RF) or SMOTE applied only on training (synthetic rows marked synthetic=True).

Three families are considered: Random Forest, XGBoost and SVM (with StandardScaler and probabilistic output). Each model produces a score \(s(x)\).

FAR-constrained threshold calibration

\[ \mathrm{FAR}=\frac{FP}{FP+TN},\qquad \mathrm{Sens}=\frac{TP}{TP+FN} \]
(2.5)

On test we report Accuracy, Precision, Recall, F1, FAR, Sens and ROC-AUC alongside the confusion matrix.

Feature selection and Optuna

An importance ranking from Random Forest orders the variables. Optuna optimises model and SMOTE hyperparameters: on each trial SMOTE is applied to train, the model is fit, the threshold is calibrated under the FAR constraint on validation, and the result is evaluated (e.g. F1).

Cluster effect: Base vs. Base+Cluster

To quantify the cluster contribution, two scenarios are compared for \(K=5,10,\dots\):

  • Base: top-\(K\) ranking variables without clusters.
  • Base+Cluster: top-\(K\) of the combined ranking.

Artefacts and XAI

The pipeline produces, under Resultados/, CSV/DuckDB feature stores, balanced datasets, Optuna outputs, iterative experiments and reproducible bundles model_history/<run_id>/<strategy>/ with model.joblib, manifest.json, background.parquet and explain_rows.parquet.

Reproducible bundle

The manifest.json persists model, hyperparameters, columns, metrics, calibrated threshold, final split, exact provenance of flow features and cluster variables, selection, and whether balancing was used. With this, the History tab reopens the explanation without recomputing features.

Explainability is computed with SHAP over two persisted subsets: up to 128 real training rows as background and up to 64 test rows enriched with representative cases (highest score, strong TP, strong FP, relevant FN). We report a global ranking by \(\mathrm{mean}(|\mathrm{SHAP}|)\), Base vs. Cluster aggregation, a cluster-specific top, and local cases. Tree models use TreeExplainer; SVM uses KernelExplainer over the positive probability.

FAR

False Alarm Rate is the main operational metric: how many alerts are issued without an actual accident. A real-time warning system requires low FAR even at the cost of sensitivity.

Temporal leakage. All splits are by time, never random — the model must not see the future.

SMOTE. Train only. Synthetic rows are flagged synthetic=True to be auditable.
