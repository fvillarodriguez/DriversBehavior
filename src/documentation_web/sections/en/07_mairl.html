MA-AIRL implementation

Goal and scope

Functional implementation of Multi-Agent Adversarial IRL following the framework of src/MAIRL.pdf. For each driver cluster we learn a stochastic policy and a reward function that explain the demonstrations, and we export vType parameters for SUMO. The architecture is split into core (src/marl_core.py) and interface (src/multi_agent_rl_app.py).

Data and state

The input is cluster CSVs with cluster_label. Each row is an expert sample with state \(s\) formed by selected numeric columns (default: avg_speed_kmh, avg_headway_s, lane_change_rate). It is standardised with a dedicated StandardScaler and split per agent (cluster).

Proxy actions

Since the CSV does not contain real actions, a proxy is built: metrics are mapped to car-following parameters (maxSpeed, accel, decel, minGap, sigma, impatience), heuristic transformations are applied, and values are clipped to PARAM_BOUNDS. Actions are normalised to \([-1,1]\) for stable training.

Models

Per agent we instantiate three networks:

  • Gaussian policy \( q_\theta(a\mid s) \) (MLP producing \(\mu\) and \(\log\sigma\)).
  • Reward \( g_\omega(s,a) \) (MLP over state-action).
  • Potential \( h_\phi(s) \).
\[ f_{\omega,\phi}(s,a,s') = g_\omega(s,a) + \gamma\,h_\phi(s') - h_\phi(s) \]
(7.1)

Discriminator and objectives

\[ D_\omega(s,a) = \frac{\exp(f_\omega(s,a))}{\exp(f_\omega(s,a)) + q_\theta(a\mid s)} \]
(7.2)

Implementation
src/marl_core.py · MAIRL training loop (no explicit D function)

The discriminator maximises \( \mathbb{E}_{X_E}[\log D] + \mathbb{E}_{X_\pi}[\log(1-D)] \); the policy maximises \( \mathbb{E}_{X_\pi}[f_\omega(s,a) - \log q_\theta(a\mid s)] \) (Eq. 12 of the paper).

SUMO FCD trajectories

The active implementation builds \(s, a, s'\) from consecutive SUMO FCDOutput samples. SUMOPy remains a conceptual reference, but it is not added as a dependency because of its historical Python 2.7/wxPython stack.

SUMO export

When training finishes, the policy is evaluated at the mean state and parameters are de-normalised to SUMO ranges. The generated file is mairl_vtypes.add.xml, with one vType per cluster.

UI and metrics

The interface offers an algorithm selector: MA-AIRL (SUMO FCD) vs CEM (legacy), import/generation of sumo_fcd.xml, and controls for batch size, \(\gamma\), learning rates, network size and device. During training, disc_loss, policy_loss and reward_mean are reported.

Limitations and next steps

  • The fidelity of \(s'\) and real actions depends on the FCD period; the default is 1 second.
  • Headway is estimated by time, edge, lane and position within the FCD.
  • There is no \(s'=s\) fallback: MA-AIRL requires valid FCD transitions.

MA-AIRL

Multi-Agent Adversarial Inverse Reinforcement Learning: simultaneously learns a policy and a reward that explain the demonstrations, without assuming a known reward function.

Per cluster. One policy and one reward per driver cluster — captures heterogeneous behaviours in a single run.

SUMO export. The final product is vType parameters that can be loaded directly into a SUMO simulation to reproduce observed heterogeneity.
