Chapter · Multimodal severity

NLP severity modelling

Objective and scientific contract

This chapter models crash severity with a tabular-multimodal architecture that combines observed traffic conditions around the event and semantic representations extracted from the crash narrative. The task does not predict occurrence, as in chapter 2; it starts from already identified events and estimates a binary severity label severity_target, where the positive class is MARC and the negative class is No-MARC.

The implementation is concentrated in src/nlp_severity_app.py. The chapter protocol compares three input families: M1, flow variables only; M2, textual embeddings only; and M3, fused flow and text. The methodological contribution is to separate precisely what signal comes from traffic, what signal comes from the textual description, and how much early multimodal fusion improves classification under the same holdout, feature-selection grid and model family.

Observational unit and target

The observational unit is crash \(i\), not a portico-time cell. Each record combines temporal and spatial event attributes, a severity label, flow variables extracted around accidente_time, and a normalized text field text_bert built from fields such as kilometre, axis, carriageway, subtype and description. This definition turns severity into an event-level multimodal classification problem.

Flow variables around the crash

The raw route rebuilds traffic variables from the flow database. For each crash it queries one-minute windows before and after the event, with five windows in each direction by default. The route computes flow, speed_mean, speed_std and density; it then assembles a wide matrix by crash and adds temporal deltas when include_deltas=True.

\[ W_i=\{[t_i+m\Delta,t_i+(m+1)\Delta):m=-5,\ldots,4\},\qquad \Delta=1\text{ minute}. \]

Narrative text and embeddings

The textual signal comes from text_bert, a compact crash narrative. The implementation uses the latest compatible fine-tuned Transformer registered in the system, loads tokenizer and encoder through AutoTokenizer and AutoModel, and extracts representations from the [CLS] token. In this route, text is cleaned with fillna(""), conversion to string and str.strip(); the step does not force lowercase because the Transformer encoder preserves case and subword context.

Three input modalities

The central comparison is implemented as a block-level feature ablation. M1 measures what flow can explain without text; M2 measures what text can explain without traffic; M3 measures early fusion of both spaces. The three modalities use the same classifier family, target and test IDs so that metrics remain comparable.

\[ X^{M1}=X^{flow},\qquad X^{M2}=X^{emb},\qquad X^{M3}=[X^{flow}\Vert X^{emb}]. \]

Temporal split and leakage prevention

By default, crashes are ordered by accidente_time and the final 20% is reserved as test. The temporal split prevents future events from influencing training. If the temporal cut does not contain both classes in train and test, _prepare_holdout_split_with_ids uses a stratified split with random_state=42 and records it in metadata.

\[ \mathcal{D}_{train}=\{i:t_i\lt T_{0.8}\},\qquad \mathcal{D}_{test}=\{i:t_i\ge T_{0.8}\}. \]
(3.10)
Invariant

Test never receives test-fitted imputation, SMOTE, or ranking recalculated with test information.

Anti-leakage rule

Median imputation, Random Forest ranking and SMOTE are fit only on the training block or the corresponding inner fold. Test is transformed with previously learned parameters and remains real.

Feature ranking and \(k\) grid

Before XGBoost training, the pipeline computes a modality-specific feature ranking. For each \(k\), the model uses the \(k\) highest-importance columns, clipped automatically when the modality has fewer variables than requested. The manual grid preserves the protocol values, while interval mode enables dense sweeps controlled by step size.

\[ S_k=\operatorname*{arg\,top}_{S:|S|=k}\ I_j^{RF},\qquad X_k=X[:,S_k]. \]
(3.11)
Order

The ranking is computed before SMOTE, so feature selection does not observe synthetic rows.

XGBoost, SMOTE and nested cross-validation

The model family is fixed to XGBoost. For each modality and each \(k\), training uses nested cross-validation with stratified outer and inner folds. The inner fold optimizes XGBoost hyperparameters and SMOTE parameters; the best model is then fit on the balanced outer-training fold and evaluated on the untouched outer-validation fold.

\[ \hat f_{k,\lambda,\gamma}= \operatorname*{arg\,max}_{\lambda,\gamma} \mathrm{CV}_{inner}\bigl(f_{\lambda},\mathrm{SMOTE}_{\gamma}(X^{train}_k,y^{train})\bigr). \]
(3.13)
Parameters

\(\lambda\) denotes XGBoost hyperparameters; \(\gamma\) groups SMOTE sampling_strategy and k_neighbors.

The optimization backend can be gridsearch or optuna. Under Optuna, PAPER_OPTUNA_TRIALS_DEFAULT sets 24 trials by default. CV folds accept values from 2 to 10 and default to 5.

Metrics, selection score and clinical reading

Final metrics are computed by _classification_metrics. Besides accuracy, precision, recall, F1, balanced F1, MCC and ROC-AUC, the pipeline records the confusion matrix, per-class metrics and false negatives for the positive class. In this implementation, false_negative_rate_positive_class is defined as MARC false negatives divided by the total evaluated set size, not by the positive support.

\[ \mathrm{F1}=\frac{2\,\mathrm{Precision}\,\mathrm{Recall}}{\mathrm{Precision}+\mathrm{Recall}}, \qquad \mathrm{FNRate}_{MARC}=\frac{\mathrm{FN}_{MARC}}{N}. \]
(3.14)
Important

The denominator of FNRate is \(N\), the total number of evaluated rows. This convention yields a smaller numeric value than \(\mathrm{FN}/P\).

\[ \mathrm{Score}_{val}= \begin{cases} \mathrm{best\_score}_{CV}, & \text{if GridSearchCV or Optuna provides it},\\ \mathrm{F1}, & \text{if no internal score is available}. \end{cases} \]
(3.15)
Current implementation

_paper_validation_score prioritizes best_cv_score. The constant PAPER_VALIDATION_ALPHA=0.3 remains persisted in the protocol, but it does not drive selection when an internal score exists.

Execution routes and checkpoints

Execution is designed to be resumable. Each run creates a central manifest, live status and a JSONL event log. The frozen, raw and update_embeddings routes produce their own subdirectories, making it possible to distinguish evaluation of the frozen dataset, reconstruction from original sources and optional embedding refresh while keeping flow variables fixed.

Route comparison and documentation promotion

Route comparison separates discrete quantities from continuous metrics. Discrete quantities, such as number of rows, variables, classes and splits, must match exactly. Numeric metrics accept an absolute tolerance of 0.001, defined by PAPER_COMPARISON_TOLERANCE. If comparison fails, export is blocked so documentation cannot show results without traceability.

\[ |m_{raw}-m_{frozen}|\le 0.001. \]
(3.16)
Tolerance

The tolerance applies to continuous metrics. Counts, classes, model names and artifact availability are compared exactly.

Documentation assets include accuracy_vs_k.png, f1_score_vs_k.png, false_negatives_pct_vs_k.png, validation_score_vs_k.png, metrics.png, gridsearch_k.tex and metricas_modelos.tex. Promotion is not a blind copy: it depends on manifest state, route-comparison status and the presence of candidate files.

Methodological audit against the manuscript

The implementation preserves the experimental structure of the manuscript, while adding engineering decisions needed to make the protocol executable, resumable and verifiable. The following differences must remain explicit in the documentation because they affect interpretation, reproducibility and result comparison.

  • The Transformer encoder is not trained inside this execution; the latest compatible fine-tune in the registry is reused and its encoder representation is extracted.
  • The Transformer route does not force lowercase; lowercasing is restricted to alternative TF-IDF-style paths.
  • Textual reduction is fixed to the top-200 dimensions by Random Forest ranking, instead of leaving an abstract dimension \(p\).
  • Feature ranking is modality-specific and happens before SMOTE.
  • The \(k\) search runs for M1, M2 and M3, not only for the fused modality.
  • SMOTE is optimized inside the inner search together with XGBoost; it is not applied as a global preprocessing step.
  • The preferred holdout is temporal; stratified splitting is used only as a fallback when the temporal cut does not preserve both classes.
  • \(k^\ast\) selection uses the best observed score with the smallest-\(k\) tie break, not a marginal-gain rule.
  • Search profiles and the Optuna backend control computational cost without changing experiment semantics.
  • Routes, checkpoints and tolerance-based comparison are software safeguards; they do not change the statistical hypothesis, but they increase traceability.
Residual risks

No-MARC is the minority class, so aggregate metrics can hide clinically relevant errors. Interpretation should prioritize per-class metrics, MARC false negatives, the confusion matrix and \(k^\ast\) stability across modalities.
