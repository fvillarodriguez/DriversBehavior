Capítulo · Reward Learning con SUMO FCD

Manual operativo de MA-AIRL

Qué hace esta UI

La página Reward Learning aprende políticas y recompensas que explican trayectorias expertas generadas por SUMO. La implementación activa exige transiciones reales \(s,a,s'\) desde muestras consecutivas de FCD; no entrena MA-AIRL con AVI ni con el antiguo fallback \(s'=s\). El flujo vive en src/multi_agent_rl_app.py, el núcleo en src/marl_core.py y la reconstrucción FCD en src/SUMO.py::build_sumo_fcd_transition_dataset.

Flujo de configuración

  1. Trayectorias expertas desde SUMO FCD. Indica .sumocfg, tripinfo.xml, sumo_fcd.xml y el periodo FCD. Ejecutar SUMO y construir transiciones FCD llama a sumo/sumo-gui con --fcd-output y --fcd-output.acceleration true. Importar FCD existente parsea directamente un XML FCD ya generado.
  2. Features del estado. Después de reconstruir transiciones, la UI lista columnas state_*, flow_context_* y vms_active. Los defaults salen de DEFAULT_STATE_COLS: velocidad, carril, headway, velocidad relativa, contexto de flujo y VMS.
  3. Clústeres opcionales. Los archivos Resultados/cluster_*.csv sirven para análisis o nombres de políticas; no reemplazan el FCD experto.
  4. Parámetros SUMO. Duración, paso, GUI y estrategia de emisión apoyan corridas y rutas SUMO, pero no cambian un dataset FCD ya importado.
  5. Diagnóstico AVI y pórticos. Reconstruye transiciones AVI parciales para inspección. La UI las separa explícitamente del entrenamiento MA-AIRL.
  6. Políticas compartidas. La configuración se deriva de agent_id; el usuario puede ajustar número y nombres antes de entrenar/exportar.
Contrato de entrada

is_sumo_fcd_transition_dataset exige source="sumo_fcd". Si las transiciones están vacías, vienen de AVI o no tienen esa procedencia, el botón de entrenamiento MA-AIRL rechaza la corrida.

Dataset experto

build_sumo_fcd_transition_dataset recorre el XML FCD con iterparse, ordena muestras por vehículo y tiempo, y forma una transición por cada par consecutivo. La tabla resultante contiene identificadores (trajectory_id, agent_id), estado/siguiente estado (state_speed_kmh, next_speed_kmh, carril, posición, coordenadas, headway), contexto de flujo y acciones observadas (action_delta_speed_kmh, action_accel_m_s2, action_lane_change).

Entrenamiento MA-AIRL

En MA-AIRL (SUMO FCD), la UI usa temporal_split == "train" cuando existe, instancia MAIRLManager y ejecuta train_step(batch_size) durante las iteraciones indicadas. Los controles son Iteraciones, Batch size, \(\gamma\), LR Policy, LR Reward, Hidden units y Device; auto resuelve cuda, mps o cpu.

\[ f_{\omega,\phi}(s,a,s') = g_\omega(s,a) + \gamma\,h_\phi(s') - h_\phi(s) \]
(7.1)
Variables
gω(s,a)
Red de recompensa sobre estado y acción.
hφ(s)
Potencial de estado usado para shaping.
qθ(a∣s)
Política gaussiana aprendida por agente.
Implementación
src/marl_core.py · MAIRLAgent.f · MAIRLManager.train_step

Por cada agent_id, el manager crea una política gaussiana \(q_\theta(a\mid s)\), una red de recompensa \(g_\omega(s,a)\) y un potencial \(h_\phi(s)\). En cada iteración muestrea transiciones expertas y acciones de política, actualiza recompensa/potencial con la pérdida adversarial y luego actualiza la política con la recompensa formada.

Métricas y exportación

La UI guarda disc_loss, policy_loss, reward_mean, agents y transitions en st.session_state["mairl_metrics_log"]. El botón Exportar perfiles MA-AIRL escribe simulación/mairl_policy_profiles.json con feature_cols, action_cols y policy_actions desnormalizadas desde el estado medio de cada política.

Limitaciones actuales

  • La fidelidad de \(s'\) y de las acciones depende del periodo FCD; el default de la UI es 1 segundo.
  • Headway y velocidad relativa se estiman dentro del FCD por tiempo, edge, carril y posición.
  • AVI es diagnóstico, no fuente de entrenamiento MA-AIRL.
  • CEM (legacy) sigue disponible como comparación heurística, no como flujo MA-AIRL principal.
